## 0.1.0

Initial port of the `@ianmenethil/zp-hcp@0.1.30` shared/server API surface:

- SHA3-512 fingerprint generation (`createZpFingerprint`) for the Authorise request.
- Hosted-checkout Authorise launch URL construction (`createZpCheckoutUrl`) with single-pass percent-encoding.
- Fixed `createZpCheckoutUrl` query string encoding to preserve `=` for empty-string parameters, matching TypeScript SDK behavior instead of Dart's `Uri.replace` default.
- Server-to-server callback authenticity verification (`verifyZpCallback`, `validateZpCallbackBody`) across payment, custom payment, preauthorization, and tokenisation modes.
- Stateless HMAC-SHA3-512 signed callback URL tokens (`createZpCallbackUrlToken`, `verifyZpCallbackUrlToken`) for correlating returns without server-side session state.
- Wire enums (`ZpPluginMode`, `ZpDisplayMode`, `ZpUserMode`, `ZpOverrideFeePayer`, `ZpPaymentStatus`) and shared crypto/ID primitives (`createSha3_512`, `createZpMupid`, `createZpTimestamp`, `zpAmountToCents`).
- Fixed string interpolation bug in the secret-length `ArgumentError` message (`createZpCallbackUrlToken`, `verifyZpCallbackUrlToken`) that caused the literal identifier to be rendered instead of the required minimum byte count.
- Fixed `createZpCallbackUrlToken` payment amount validation to reject non-finite numbers (`NaN`, `Infinity`), preventing `JsonUnsupportedObjectError` crashes and aligning with TypeScript SDK behavior.
- `createZpCheckoutUrl` now falls back to a default `title` query parameter when the caller omits it: `"Tokenize Card"` for `ZpPluginMode.tokenise`, `"Process Payment"` for every other mode. An explicit `title` always overrides. Only the `"Process Payment"` value and the height hints below are ported from the TypeScript SDK's `ZP_DEFAULTS`; the per-mode title split is a zenpay_dart-specific addition with no TypeScript equivalent. `ZpUrlSuccess` also now carries a `height` hint (`"450px"` for `ZpPluginMode.tokenise`, `"725px"` otherwise), matching `ZP_DEFAULTS.HEIGHT_TOKENISE`/`HEIGHT_DEFAULT`, and a `maxWidth` hint (always `"600px"`), matching `ZP_DEFAULTS.WIDTH_MODAL`. Both are informational — the TypeScript SDK itself documents them as ignorable by the renderer.
- **Breaking:** `ZpCallbackUrlTokenPayload.merchantUniquePaymentId` and `.timestamp` (in `lib/src/models/callback_token_models.dart`) changed from `String` to the package's existing type-safe wrappers `ZpMupid`/`ZpTimestamp`, matching every other model in the package. Added `ZpPluginMode.tryFromWireValue(int value)` (in `lib/src/models/enums.dart`), a null-returning counterpart to the existing throwing `ZpPluginMode.fromWireValue`, mirroring `ZpPaymentStatus.tryFromWireValue`. Internal: removed a duplicated private wire-value parser in `callback_token.dart` in favor of the new `tryFromWireValue`, and simplified a redundant condition in `crypto.dart`'s `resolveZpHashAmountChecked`.
- Migrated `ZpVerifyCallbackContext`, `ZpFingerprintInput`, `ZpCallbackUrlTokenPayload`, `ZpCallbackUrlTokenOptions`, and `ZpCheckoutOptions` to Dart's primary-constructor syntax, matching the wire enums' existing style. No field name, type, nullability, default, or public API shape changed. `public_member_api_docs` is now disabled package-wide in `analysis_options.yaml` — the lint can't recognize a doc comment on a class primary constructor, and has no per-construct granularity to exempt just these classes; every exported member still carries a doc comment by convention.
- `checkout_url.dart` no longer validates `paymentAmount` in the URL builder, matching TypeScript SDK behavior (fingerprint/hash-pipe validation remains); `crypto.dart`'s `constantTimeHexEqual` reimplemented as direct char-code XOR loop matching TS's `timingSafeEqualHex` with no behavior change for equal-length inputs; `callback_token.dart` doc comments now explicitly state `ArgumentError` throws for malformed payload/secret; removed unused error constants `ZpErrors.amountRequired` and `ZpErrors.bodyEmpty` from `constants.dart`.
